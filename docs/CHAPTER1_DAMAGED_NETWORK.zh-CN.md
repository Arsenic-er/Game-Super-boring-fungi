# 第一章损伤网络存读档交叉回归

## 范围与已有覆盖

本项补齐 `tests/damaged_network_save_smoke.gd`，不新增玩法或修改生产代码。

- `tests/smoke_test.gd` 已检查核心死亡、孤立菌丝衰败和接管，但救援菌丝由夹具直接添加成熟段，且未跨存读档。
- `tests/offline_async_load_smoke.gd` 已检查高密度存档分帧加载；本项沿用其返回时间 750 ms、结算 30,000 ms、最多 2,400 帧的门槛。
- `tests/developer_mode_smoke.gd` 已独立检查开发者与普通档隔离；本项额外覆盖真实损伤、接管后的网络状态在两档中的保存和恢复。

## 受控场景与验收

起始夹具放置三个正常存活核心，没有写入最终死亡或接管状态。默认保留真实生成地图的 3,147 个活资源及其序列化路径，让标准 CI 持续覆盖此次发现的慢加载场景；可选 `--depleted-resources` 耗尽可采资源以单独诊断网络持久化。初始菌丝和救援菌丝均调用玩家使用的 `_confirm_extension`，实际扣除有机营养，再经 `_update_growth` 推进生长。

1. 两个核心先经 `_damage_core` 受损，再由附近细菌触发 `_update_core_hazards` 的真实毒素死亡。剩余核心让游戏保持可经营；死亡核心的 DNA 队列清空。
2. 两条孤立网络经 `_update_orphaned_segments` 缓慢衰败。接管前保存并重新加载，死亡、剩余活性均保留；对死核心申请修复不复活、不扣费。
3. 存活核心合法延伸至一条孤立网络，随着生长产生接触并触发接管；未接触的另一网络不被误接管。
4. 接管后再次保存读取，所有权、恢复的活性和另一网络的衰败进度保留；未接管段继续扣减活性而非读档重置。
5. 仅将真实序列化存档的离线时间改为 48 小时，调用 `_load_game(true)`，检查及时返回、跨帧单调进度与原有耗时门槛。结算后死核心不复活、接管段保留、遗弃段消亡，并显示报告；立即重读不能重复结算或复活已消亡结构。
6. 通过真实开发者入口切换独立存档，保存和读取后损伤拓扑仍然存在，普通档字节不变；退出开发者模式并读普通档后恢复普通档的资源与拓扑。

## 执行约束

在隔离的 HOME / Godot 用户目录执行，单项进程外部限时 120 秒。测试不覆盖已有开发者存档，发现已有主档或备份时直接失败。测试结束清理自己创建的测试存档与备份，停止临时音频并释放场景。

本项是结构与持久化回归，不是普通玩家自然经营流程或真实 48 小时耐久实测；不会据此宣称第一章平衡已完整验收。

保留完整默认活资源的诊断模式连续两次触及原 30 秒门槛。第二次精确结果为 30,033 ms / 501 帧，进度 70.3125%，结算仍在运行。此时起始夹具与标准模式的差别仅为 3,147 个资源全部可采；新图种子仍为 `0xF00D47`，两条受损网络和合法接管步骤相同。不能将这个失败视为已解决，受控测试的通过也不能替代完整地图性能验收。

## 空间候选查询修复后的复验

主代理将细菌丝发现的全图扫描替换为空间格子候选查询：查询存活核心与成熟、非孤立活菌丝周围的资源格子，曲线范围覆盖全部曲线顶点；之后仍执行原有最近来源、距离、排序、两类资源预留名额和总容量规则。不增加缓存、不修改吸收费率。正常世界 ID 等于数组索引时保留候选 ID 排序；非单调或稀疏旧记录按原资源数组顺序回退，避免同距离目标次序改变。

新增 `tests/feeder_spatial_query_smoke.gd` 将提交 `5d9e6cc` 的旧 `_discover_feeders` 全扫描逻辑保留为测试内参考。除了访问当前游戏状态及使用局部结果数组，没有将参考改写成新空间算法。比较完整有序连接字典，包括资源 ID、起点、终点、归属核心、生长值及同随机状态下的相位。

最终 50 次等价对照通过，覆盖：正常出生地图、真实最密资源热点（3,147 条记录中查询 87 个候选）、两类营养预留、同距排序、已经连接的资源、正负坐标边界、未成熟和成熟曲线、曲线偏离端点包围框、失核、孤立标志、不同核心范围、即时范围升级、开发者新增资源、稀疏与非单调 ID、重复格子记录、耗尽与离线索引裁剪、单个剩余容量及满容量。旧算法没有额外活性过滤这一点也保持等价，没有借优化改动规则。
