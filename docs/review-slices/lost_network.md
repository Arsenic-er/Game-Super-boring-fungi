# 失联网络 · lost_network

用途：审查主动开封、真实菌丝接管和修复救援，确认有风险窗口但不会刚进地图就被隐藏倒计时判败。

## 初始条件

地图种子 **8222**。有机 220.000、矿物 24.000、DNA 0、水无限；玩家的普通主核位于原点，研究／强化／建设分支均为 0，无预制军队。主巢入口等级 3，出征不享等级加成。

此外存在两处**已死亡**核心遗迹 **(420, -180)**、**(510, 170)**，以及 **(700, 210)** 的**活中继核心**，初始生物量为最大值的 **25%**。不能把“四个核心记录”解释为四个健康开局核心。通用规则见[索引](README.md)。

## 完成与失败

- 真正接管 **2 段**孤立菌丝。
- 活中继在结算时仍存活，生物量达到最大值的 **75%**。
- 本任务累计实际吸收有机营养 **420.000**；初始库存不计。
- 己方至少一个核心仍存活，且本任务未触发专属失败。

在任务面板主动开始救援后，两段长度各为 **100 世界单位**的孤网才出现，分别从遗迹位置向右伸出。未接管部分有 **900 模拟秒（15 分钟）**接管窗口；已经接管的部分不再受孤网衰败限制。不是“15 分钟内必须同时吸满 420 并修完中继”。

活中继死亡，或尚未救回的目标孤网衰败消失，会使本关失败；即使原点主核还活着也不能继续领胜利。全体核心死亡同样失败。

## 可尝试的玩法

先建立资源供给并规划接近遗迹的菌丝，再决定何时开封。开始后使用正常连接让存活核心接管孤网，同时安排中继的资源消耗型修复与持续补给。可以先救两网再继续经营，不规定左右顺序。

## 验收清单

- [ ] 初始两处遗迹不活动，中继为活体；地图不把死遗迹画成可复活的新主核。
- [ ] 未主动开始时不产生救援孤网，也不消耗其 15 分钟窗口。
- [ ] 开始按钮只成功一次；重复触发不能补回生命、重置时间或复制两段菌丝。
- [ ] 救援依赖实际孤网连接和归属转移，派部队路过或接近遗迹不能直接加目标。
- [ ] 成功接管后遗迹核心仍然死亡；活中继恢复与孤网接管是分开的目标。
- [ ] 中继只有 74% 或只有一段接管时不能结算；中继死亡应立即成为失败条件。
- [ ] 放任未接管孤网衰败后不能补造一段同位置菌丝来抹掉失败。
- [ ] 开封前后和接管一段时分别保存／读取，窗口、标记、归属与中继生物量保持一致。

## 设计边界与证据

任务标记是救援情报，不等于揭露全部地图。15 分钟按模拟时间计，加速也会加快窗口。修复所需资源仍按普通核心逻辑消费；本关不添加复活已死核心机制。两个接管成果是已发生事件，中继生物量则是结算时的实时值。
