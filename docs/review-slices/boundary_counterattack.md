# 边界反攻 · boundary_counterattack

用途：审查由经营转入主动进攻的过程，以及“指定竞争核心”是否明确、可侦察、可攻击、可证明击败。

## 初始条件

地图种子 **8224**。一个普通核心，有机 220.000、矿物 24.000、DNA 0、水无限；研究、强化和分支均为 0，无预制兵营或军队。主巢入口等级 4，出征不享等级加成。

东侧 **(850, -20)** 生成一个指定竞争真菌核心，初始／最大生物量 **40.000**、有机储备 **8.000**，带初始敌方菌丝与 **1** 名初始守卫。这不是敌人永远只有一个守卫的保证，后续行为继续走敌方菌落逻辑。详见[索引](README.md)。

## 完成与失败

- 击败本场任务记录的**指定敌方核心 ID**。
- 本任务累计实际吸收有机 **450.000**，不计初始库存。
- 至少一个己方核心仍存活。

仅击杀守卫、击败别的敌人、到达目标坐标或让目标记录在读取时丢失都不算完成。全体己方核心死亡失败；没有强制倒计时。

## 可尝试的玩法

先建立稳定资源供给，再正常建设兵营和军队。向东侦察定位目标，尝试先清守卫、拉开交战位置或集中攻击核心；同时保持资源吸收，不把所有投入都押在第一波冲锋上。普通腐生路线也可完成，不强迫先开真菌食性。

## 验收清单

- [ ] 目标核心位于东侧，初始生物量 40.000；未探索区域不能直接显露完整敌情。
- [ ] 对守卫与核心的攻击可以造成真实小数伤害，不是靠等待自动扣到零。
- [ ] 仅杀守卫不能完成核心目标；核心得到致死攻击并保留死亡记录后才算击败。
- [ ] 竞争核心死亡但有机吸收不足 450 时不能提前结算。
- [ ] 初始有机库存与普通花费不直接改变“累计吸收”的完成逻辑。
- [ ] 没有真菌食性或专属兵种时，正常付费的基础兵种路线仍具备可行性。
- [ ] 目标受伤时保存／读取，身份与血量不恢复为新品；已死亡目标也不复活。
- [ ] 指定目标记录损坏／缺失时应拒绝不完整存档或恢复有效备份，不能免费认定胜利。

## 设计边界与证据

本关是单个指定竞争核心的反攻，不是要求清空全地图敌军。初始 40 生物量只是起始配置，不意味着暂停敌方本来的回复与经营行为。自动脚本的既定微操路线不代表新手通关体验。
